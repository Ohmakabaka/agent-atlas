# 内容、主题与关系贡献

## 文件与数据形态

`data/` 保存独立 JSON 数据：

- `topics.json`：主题树、问题、概念和阅读路径。
- `articles.json`：资料、中文导读、技术要点和可选工程案例。
- `sources.json` / `organizations.json` / `people.json`：来源、机构和人物。
- `relations.json`：带证据、类型与审核状态的知识关系。

种子程序按固定 ID 或规范地址追加缺失数据，不覆盖数据库现有编辑。修改 JSON 是修改未来初始化模板；修订已有线上内容需通过后台完成，或单独编写审阅过的数据迁移。

## 技术主题格式

以下展示字段形状；新增主题须采用唯一 ID、slug 并选择真实父主题：

```json
{
  "id": "topic-example",
  "slug": "example",
  "name": "中文主题名",
  "englishName": "English term",
  "description": "技术范围、适用边界与资料线索。",
  "question": "这个主题帮助读者解决什么具体问题？",
  "concepts": ["关键概念"],
  "readingPath": ["已存在的文章-slug"],
  "featured": false,
  "sortOrder": 0,
  "color": "teal",
  "parentId": "已存在的父主题-id"
}
```

顶层主题的 `parentId` 为 `null`。阅读路径只引用实际存在的文章 slug，且应与主题关联资料相符。不要形成父子循环。专题介绍应有可跟进的原始资料，不添加缺乏证据的技术结论。

## 资料收录

资料必须能明确回答：它是什么、谁发布、何时发布、为什么与这个主题有关、原始证据在哪里。

- 中文标题应准确表达原文范围；保留原始标题，不虚构“官方”“最佳”等标签。
- 中文导读用独立表达概括范围、核心方法和局限，不把摘要扩大为未经证实的工程结果。
- 作者和所属机构按原文标注。GitHub 项目所属团队不一定等同于某篇文章全部作者的雇主。
- 缺少发布日期时留空；仓库创建时间、收录时间与特定版本发布时间不可混用。
- 工程案例分别填写问题、架构、方案、效果和依据链接。没有性能数字就不填数字，没有生产证据就不称为生产部署。
- `type` 为 `paper/article/docs/repository/podcast`。
- `layer` 为 `primary/community/engineering`，分别表示原始资料、中文解读和工程实践。
- `quality` 为 `curated/standard`，是编辑整理等级，不是来源真实性的自动保证。
- 公开内容必须经过人工核对；采集草稿与模型建议不能直接视为已审核结果。

首批资料来自真实公开链接。开发环境对部分网站的访问限制意味着仍需社区持续核验元信息；纠错时请附可验证的原始依据，不仅提供模型回答或转述。

## 知识关系

| 类型            | 含义与证据要求                           |
| --------------- | ---------------------------------------- |
| `explains`      | 内容解释某项技术，原文中有对应论述       |
| `implements`    | 项目或案例实现某项技术，有代码或设计说明 |
| `discusses`     | 对某技术提出讨论，避免误称完整实现       |
| `compares_with` | 明确比较两个方案，保留比较的范围         |
| `references`    | 原文明确引用目标内容                     |
| `extends`       | 作者明确说明扩展已有工作，附出处         |
| `challenges`    | 明确质疑某结论或方法，保留语境           |
| `related_to`    | 一般主题关联，不暗示引用或继承           |

新建议使用 `suggested`；确认后使用 `confirmed` 并提供 `evidenceUrl`。关系需要恰当的方向和恰好两个端点，不允许自关联。后台可复核和修订；前台只展示已确认且文章端点已公开的关系。

## 版权与署名

收录不是全文授权。第三方论文、博客、公众号、商标和开源项目各自保留版权与许可；本项目 MIT 许可证不覆盖这些外部材料。

默认贡献原创中文导读、元信息、原文链接与关系。不提交未授权全文、绕过付费墙获得的内容或私人群聊。确需引用时使用必要且有限的摘录，明确作者、出处和许可；无法确认授权时仅提供链接与自己的导读。

若作者要求修正署名、移除不当摘录或说明权利，请通过 issue 提供具体条目和依据。不要在公开 issue 暴露私人联系方式、访问令牌或其他敏感材料。
