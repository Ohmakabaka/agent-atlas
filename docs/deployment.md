# 部署与运行

## 本机开发

从项目根目录执行 README 的 `npm ci`、环境变量配置和 `npm run db:init`。应用、CLI、Prisma 配置均以项目根目录作为工作目录。默认数据库 `file:./dev.db` 位于 `prisma/dev.db`。

`npm run dev` 用于开发；生产构建必须先初始化数据库，再执行：

```bash
npm run typecheck
npm test
npm run build
npm start
```

`npm start` 默认监听 3000 端口，可以通过 `PORT` 调整。生产部署应置于 HTTPS 反向代理后。

## 持久化部署

推荐单实例 Node.js 服务加持久磁盘，适用于小团队编辑：

1. 安装 Node.js 22+ 并在发布目录执行 `npm ci`。
2. 通过部署环境或受保护的 `.env` 设置变量。不要把凭证写入镜像、Git 或日志。
3. 将 `DATABASE_URL` 设置为持久目录中的绝对路径，例如 `file:/var/lib/agent-atlas/atlas.db`，让服务用户拥有该目录的读写权限。
4. 执行 `npm run db:init`。首次运行导入种子；后续更新不会覆盖现有条目。
5. 执行 `npm run build`，由进程管理器以项目根目录启动 `npm start`。
6. 配置 HTTPS 和正确的反向代理主机头，再检查公开页面、后台登录与一次编辑发布流程。

SQLite 文件不能放在随请求销毁的临时文件系统中。当前实现不适合多个无共享磁盘实例同时写入各自数据库的无状态部署；若需要多实例，应先迁移数据库并改造登录限流及任务互斥。

正式部署不要设置 `ALLOW_INSECURE_ADMIN_COOKIE=true`。默认生产会话 cookie 使用 `Secure`、`HttpOnly` 和 `SameSite=Strict`；该开关只用于本机 HTTP 下验收生产构建。`ADMIN_PASSWORD` 至少 12 字符，`SESSION_SECRET` 至少 32 字符。更换会话密钥可使旧会话失效。

当前登录限流按单进程共享：每十分钟最多十次尝试，达到上限后正确密码也需等待窗口恢复。它适合受控的小团队入口，不是公网抗攻击方案；公开部署应在反向代理增加客户端限流或限制后台访问网络。多实例需要改用共享限流存储。

## 定时同步

在后台来源设置中填入真实 RSS/Atom 地址并启用来源，然后先人工运行 `npm run ingest`。CLI 从当前工作目录读取环境配置，输出汇总；存在错误返回非零状态。

确认单次运行后，可配置 cron，例如每小时第 15 分钟检查一次：

```cron
15 * * * * cd /srv/agent-atlas && /usr/bin/flock -n /tmp/agent-atlas-ingest.lock /usr/bin/npm run ingest >> /var/log/agent-atlas-ingest.log 2>&1
```

上述目录、Node/npm 路径和日志路径是部署示例，按机器实际情况调整；提前创建可写日志位置并配置轮转。使用互斥锁避免上一次任务未完成时重复启动。自动采集仅生成待审核记录，不自动发布。

当前没有持续驻留调度器，发布环境或重启服务也不会自动启用 cron。

## 备份与升级

数据库、用户配置与 Git 源码是不同资产。`data/` 只含种子，不包含后台编辑的全部数据。

升级前保留数据库备份和当前代码版本。SQLite 可使用一致性备份机制；不要在写入过程中仅复制单个数据库文件而忽略 WAL。也可以停止自己管理的应用与同步任务后，备份数据库及有关日志文件，再恢复服务。

升级步骤：安装锁文件中的依赖，应用迁移，构建，启动并验证。不要对保留编辑数据的数据库执行未经审查的 reset。种子重跑不会删除内容，也不会用 JSON 中的修订覆盖已有记录。

迁移 PostgreSQL 不是仅替换 URL：需要 datasource 和适配器调整、目标数据库迁移、数据搬迁及查询语义验证，详见 [架构说明](architecture.md)。

## 故障定位

| 现象                   | 检查                                                                 |
| ---------------------- | -------------------------------------------------------------------- |
| 页面提示无法加载       | 是否在项目根目录运行，数据库 URL 是否正确，迁移是否完成              |
| 无法登录               | 密码/密钥长度、生产 HTTPS、cookie 配置、十分钟内登录限流             |
| URL 导入只有链接       | 目标网络、DNS、页面访问限制；可继续人工填写元数据                    |
| RSS 任务失败           | feed 格式、来源启用状态、出口网络和任务错误记录                      |
| AI 不可用              | 可选密钥是否存在、HTTPS 服务地址、模型名和任务错误；人工流程不受影响 |
| 种子修改未反映在已有库 | 这是保留编辑的幂等策略，应通过后台或单独数据迁移修订                 |

在公开报告问题前移除日志中的密钥、Cookie、含凭证 URL 和个人信息。不要通过关闭 TLS 或允许私网抓取来消除网络错误。
